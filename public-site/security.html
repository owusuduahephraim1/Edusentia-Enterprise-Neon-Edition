TRUST & SECURITY

Accountable school operations begin with trust.

An overview of how the Edusentia Enterprise Neon Edition approaches identity, authorization, student records and public document verification.

Access with purpose

Edusentia uses tenant-based school accounts, role-aware permissions and server-side authorization. School roles are designed to see only the workflows permitted by their access and institutional configuration. Security-sensitive administration is protected by multi-factor authentication.

Segregated institutional records

Schools are provisioned with isolated database contexts, and access to records is enforced by the application service rather than the browser alone. File storage uses school-scoped object paths and access checks.

Document verification

Supported ID cards, issued certificates, report cards and academic transcripts can be checked through verify.edusentia.com. The live verification result, not the printed QR itself, determines the document's current status. Revocation, replacement and expiration are handled by the relevant workflows.

Operational resilience

The application includes audit and backup-related functionality. Backup completion, restore testing and off-site recovery must be verified as part of each institution's operational readiness; the existence of a backup feature alone is not a guarantee of recoverability.

Responsible use

Authorized users should protect their passwords, passkeys or one-time authentication codes. Never send login credentials, recovery codes or private student records through a public contact channel.

Technical scope: This is a product security overview, not an independent security certification, audit report or contractual security commitment. Deployment and access configurations may evolve.
